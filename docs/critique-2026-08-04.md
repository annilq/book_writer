## 设计专属性判定（Design Specificity）

**结论：弱锚定（mostly transferable）**。

仅一个界面有真实的产品专属锚定：`BookOutlineForm.tsx` 的双模式卡片用书籍工作流文案、含书籍品类分类法、三个具体示例书、"书架" 术语；`AgentProgress.tsx` 用领域术语命名四步（Prepare→Outline→Chapters→Complete）。这比通用模板多。

但锚定**停在门口**。首页之后的所有界面都是「带树侧栏的通用 LLM 聊天」：
- **阅读视图里没有「书」**。`app/books/[id]/page.client.tsx:37-41` 只渲染 `chapter.content` 进 `w-[1000px]` 灰盒，**章节标题从不渲染**；`@tailwindcss/typography` 已装但 `prose` 全程未用。这是产品的交付物页面，排版设计为零。
- **工作台 = 聊天 + 树**。把 "book/chapter" 换成 "report/section" 或 "course/lesson"，`chats/[id]`、`content/[id]`、`chat-box`、`tree` 无需任何改动。
- **品牌出现一次即消失**。`--brand` 仅出现在首页 hero、5% 透明度的模式卡、一行确认文案、`/docs` 图标；整个工作台与聊天界面中 brand 出现零次。
- 代码里唯一的「书形」元素是 `Books.tsx:44-50` 的 3:4 封面位，却用 `/placeholder.svg` 填充。

判据：一个写书产品应让**手稿**成为英雄对象，这里英雄对象是消息列表。

## 总体印象

视觉基线（Geist/cladcn + 语义令牌）是合格的、克制的；`AgentProgress` 是真正设计良好的等待界面。但跨三个界面的**交互契约尚未建立信任**：核心动作（Enter 发送、提交大纲、保存章节、放弃编辑）要么静默失败、要么无确认、要么误导图标。最大机会——也是最深问题——在于**「完成一本书」这一产品整个价值主张的终点几乎没有仪式感**，而起点则把一个有空白页恐惧的作者推去配 LLM。

---

## 做得好的地方

1. **`AgentProgress.tsx` 是真正设计良好的等待界面**：四步 stepper + 数值/百分比章节进度 + 带时间戳的活动日志 + RUNNING/DONE/FAILED 横幅 + 内联重试；用 `--success`/`--destructive` 语义令牌而非临时色；终态轮询关闭有处理。它应成为其余界面的质量标杆。
2. **双模式选择器是正确 IA 决策且位置正确**：把「自主 vs 对话」的分叉放在表单**之前**而非埋成复选框，用户理解自己在选工作流。文案专属且诚实。执行弱（见 P1），结构判断对。
3. **`globals.css` 语义令牌架构纪律性好、易扩展**：`--brand`/`--success`/`--warning` 单一来源 + 独立暗色值；组件消费 `bg-success` 而非 `bg-green-500`。这意味着下面的对比度/主题修复**成本低**（少数令牌编辑，非逐组件重构）。

## 优先级问题

### [P0] 聊天输入框 Enter 发送失效
- **What**：`components/Chat/chat-box.tsx:83-88`。keydown 调 `form.handleSubmit(onSubmit)` 却丢弃了返回的处理器；Enter 只 `preventDefault()`（吞掉换行）然后什么都不做。唯一发送方式是 24×24px 无标签箭头按钮（`:96-101`）。
- **Why**：这是 AI 产品首要界面的首要交互。每个用户本能按 Enter，结果文本停在那、无换行无发送，静默失败。Alex 15 秒流失；Casey 在移动端要戳 24px（44pt 下限的 45%）；Sam 无可朗读名。
- **Fix**：`onKeyDown={form.handleSubmit(onSubmit)}` 加 `e.key==="Enter" && !e.shiftKey && !isStreaming` 守卫；发送按钮放大到 `h-9 w-9`（触屏 `h-11 w-11`），加 `aria-label={t("send")}`，`disabled={isStreaming||!trim()}`；加「⏎ 发送 · ⇧⏎ 换行」提示与**流式中的停止**控制（当前长生成无法中止）。
- **建议命令**：`/impeccable harden`

### [P0] 阅读视图不是「书」
- **What**：`app/books/[id]/page.client.tsx:37-41` + `components/content.tsx`。固定 `w-[1000px]`（无响应式回退，<1000px 横向破损）；**章节标题从不渲染**，仅 `chapter.content`，父/非叶子章节传入 `null` 渲染为空；已装 typography 却不用 `prose`；全局 `p{@apply text-muted-foreground}`（`globals.css:216`）使正文约 **4.3:1**（低于 4.5:1）灰字。导航是 `fixed right-16 bottom-16` 的无标签 `<Menu>` FAB；无空状态、无导出。
- **Why**：这是交付物。上游一切都为产出此屏，而它现在像 debug dump。看不到章节标题，用户无法验证 AI 产出的是**结构化**的书——这正是定位主张。
- **Fix**：每节渲染 `<h2>{chapter.position} · {chapter.title}</h2>` 并跳过 null 节点；`w-[1000px]`→`w-full max-w-[68ch] px-6 mx-auto`；内容包 `prose prose-neutral dark:prose-invert`，并将 muted-`p` 规则限定作用域不进 `.prose`；阅读正文改 `text-foreground`；给大纲触发加 `aria-label`+文字标签并在 `lg:` 提升为常驻侧栏；加空状态与导出。
- **建议命令**：`/impeccable typeset`

### [P1] 破坏性操作无确认、无撤销、图标误导
- **What**：四条无防护破坏路径——①`chats/[id]/page.client.tsx:83` 编辑消息调 `removeMessagesAfterMessageId` **硬删下游全部 DB 记录**无对话框无撤销；②`content/[id]/components/outline.tsx:79` `<Play>` 图标调 `clearMessageOfChapter` 销毁该章历史（播放图标销毁工作是欺骗性 affordance）；③`BookOutlineForm.tsx:298` 点示例 `form.reset(data)` 静默覆盖已填表单；④`book-viewer-layout.tsx:98-103` 唯一带 AlertDialog 的动作执行 `extractFirstCodeBlock(...)!`+`JSON.parse(...)` **无保护**——大纲 JSON 畸形时在处理函数内抛错，对话框卡住、无反馈。
- **Why**：风险语法倒置——可恢复动作有确认，不可逆动作反而跳过。#4 意味着产品核心提交动作在用户最投入的时刻**可完全静默失败**。
- **Fix**：编辑重发/章节重生成加 AlertDialog；`<Play>`→`<RotateCcw>`；表单 `isDirty` 时才填充示例；大纲提交包 try/catch，接入既有「Try to fix」流程，payload 不解析时禁用保存。
- **建议命令**：`/impeccable harden`

### [P1] 启动页让「想写书的作者」去配 LLM
- **What**：`BookOutlineForm.tsx`。`model: z.string().min(1)` 必填无默认；选项 `qwq-32b/alibaba`、`deepseek-r1/alibaba`、`deepseek-reasoner/deepseek`；全应用零 `FormLabel`（全 placeholder）；校验信息是未翻译开发字符串（`"bookName must be at least 2 characters."`）；模式选中态 `border-brand bg-brand/5`（5% 透明，近不可见），无 `role="radiogroup"`/`aria-checked`/`role="status"`；`grid-cols-2` 无断点 <400px 挤压；`SUGGESTED_PROMPTS` 模块加载时调 `i18n.t()`（语言解析前，示例卡英文回退），且硬编码 `model:"alibaba/deepseek-r1"` 可能不在拉取列表中注入非法值。
- **Why**：Maya（项目角色）定义为空白页瘫痪者，这屏先递给她一个无依据的技术决策且无推荐默认；所选模式选中后不可见；未登录则 `createBook` 返回 null、按钮静默停住。
- **Fix**：模型给精选默认并移入「高级」；选项按结果语言标注（"均衡—推荐"/"最高质量更慢"）；每字段加 `FormLabel`；zod 信息入 i18n；选中模式卡给真实选中态（2px `border-brand`+打勾+`role="radiogroup"`/`aria-checked`），`sm:` 下 `grid-cols-1`；CTA 按 session 门控显示「用 GitHub 登录开始」而非静默 no-op；`SUGGESTED_PROMPTS` 改为 render 时求值函数。
- **建议命令**：`/impeccable onboard`

### [P2] 终点无仪式、等待无安抚
- **What**：完成整本书只弹**一个 toast**（`content/[id]/page.client.tsx:85-98`，按钮硬编码 `"Okay!"`）；保存单章 `setMessages([])` 空白屏无确认无进阶；等待侧 AgentProgress 无 ETA、无「可安全关闭本页」文案、无返回导航（`agent/page.tsx` 裸渲染无 header）、无 `aria-live`；`load()` 无 `catch` 一次失败永久冻结；`!progress?.run` 分支用刺眼 destructiv red 且可能在 run 写入前瞬现。
- **Why**：峰终定律应用于「完成」即承诺的产品。峰（成书）是 5 秒角落 toast；终（阅读视图）是灰墙文字。而最高焦虑时刻——fire-and-forget 后台任务无法验证——零安抚「走开是否安全」。
- **Fix**：完成用整屏庆祝（标题、章节数、字数、主操作「读你的书」/「导出」）；章保存内联「第 N 章已保存 ✓」并自动选下一章；agent 页加返回书架 header + 「可安全关闭本页，我们继续写」+ 粗估时 + `aria-live="polite"` + 日志自动滚动 + 轮询 `try/catch` + 瞬态未开始态改中性处理。
- **建议命令**：`/impeccable delight`
